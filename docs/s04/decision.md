# S0.4 最小授权协议决策

状态：**通过固定测试边界门，决策为 `S04_AUTHORIZATION_GATE_PASSED`**

设备：Redmi `23078RKD5C` / Android 13 / MIUI 14

版本：`0.0.4-s04` / UserService v4

日期：2026-08-08

## 决策

S0.4 选择并实施“服务端派生身份与一次性能力”方案。UserService 不再接受客户端声明的 owner UID，而是在 AIDL 入口捕获 Binder calling UID，验证其映射到固定控制包并解析当前安装签名。会话同时绑定随机能力、不可变规则快照、单调时钟租约和 owner Binder；最终 stopped/前台复核、授权判定与 `input keyevent 4` 启动共享同一进程内串行化边界。

在当前固定测试范围内，安全、性能和生命周期门均通过，因此允许继续下一阶段 Advanced 架构与安全验证。该结论不推翻 Standard S0 No-Go，也不授权消费者发布。

## 观察与推断

观察到的事实是：目标设备上的 Binder UID、固定包 UID 和签名解析一致；所有正式会话身份检查通过；正样本和生命周期矩阵没有越权动作；Back P95 未越过性能门。由此可以推断，方案 2 在这台设备和固定组件范围内关闭了客户端声明 UID、进程内重放、无独立租约及本地 check/start 间隙。

这不是跨设备或生产级安全证明。尤其不能由单机 `0/15` 推断消费者场景误动作率已达到发布要求。

## 剩余风险

- package force-stop 与 `input` 进程启动无法成为 Android 系统级原子事务；线性化点之后发生的外部状态变化仍有不可消除竞态；
- session/capability 重放记录只存在于一个 UserService 进程，服务重启后不会持久保留；
- 当前签名由同一 APK 中的服务解析，没有独立签名发行者或持久信任根；
- 自动化 Activity Intent 是测试入口，不是消费者授权界面，发布构建前必须收口或移除；
- 多用户、工作资料、双开、其他 OEM/Android 版本和真实第三方目标尚未验证；
- 允许流程仅 15 次，其 Wilson 95% 上界仍为 `20.39%`。

## 下一阶段约束

下一阶段可以继续设计真实规则的创建、确认与撤销边界，但不得扩大动作目标或启用 L3–L5。若需要跨 UserService 重启拒绝重放、多入口创建规则或持久授权，应重新评审独立签名授权代理，而不是扩展当前进程内能力集合。
