# S0.3 Shizuku 生命周期门槛决策

日期：2026-08-03

设备：Redmi `23078RKD5C` / Android 13 / MIUI 14

决策：**`STOP_UNTIL_FORCE_STOP_FAIL_SAFE`**

## 决策摘要

- 七个必测生命周期场景均有有效样本，证据覆盖门通过；
- 普通 UI 进程崩溃后，受控伴侣完成 `1/1` 次动作，韧性观察通过；
- Shizuku 正常结束及强制断连后伴侣均停止，后续跳转 Back 为 `0`，安全放行通过；
- Shizuku 重启后既有授权、绑定和动作链恢复，`1/1` 通过；
- 手机重启后的冷启动不自动拉起 Shizuku、伴侣或测试应用，通过；
- 解锁后显式恢复服务，既有授权与动作链 `1/1` 通过；
- 显式 force-stop UI 包后，shell 伴侣仍发送了 `1` 次 Back，违反停止边界。

因此，S0.2 的特权执行能力仍然可行，但当前生命周期协议不安全。Advanced 路径在修复并复测 force-stop 失效安全之前停止。

## 停止范围

在新门槛通过前，不允许：

- 把 S0.2 伴侣接入真实第三方应用规则；
- 开始消费者 Advanced 功能或发布工作；
- 在 UI/控制端消失后继续使用无期限的旧武装状态；
- 开始 force-stop、suspend、disable 等 L3-L5 功能；
- 将“技术执行可行”描述为“生命周期安全”或消费者版 Go。

允许继续：

- 设计短时授权租约、Binder 死亡处理和原子解除武装；
- 实现并测试 UserService destroy/退出路径；
- 增加 force-stop 后的多次、延时、锁屏与竞态负样本；
- 重新执行本 S0.3 门槛。

## 重新开门条件

新的实现至少必须证明：

1. force-stop 后所有后续测试跳转的特权动作均为 0；
2. 伴侣在控制端死亡或租约到期后退出，或进入可验证的不可动作状态；
3. 每次动作在发送前重新验证有效租约、会话、目标和武装状态；
4. Shizuku 断连和手机重启继续安全放行且不隐式恢复武装；
5. 普通 UI 崩溃最多保留产品明确规定的有界能力，不产生永久孤儿伴侣；
6. 机器报告决策变为 `LIFECYCLE_GATE_PASSED`。

Shizuku 官方文档明确指出 UserService 运行于独立 root/shell 进程，停止绑定不会自动杀死服务进程，应用必须实现 destroy 与退出逻辑；参见 [Shizuku API UserService](https://github.com/RikkaApps/Shizuku-API#userservice)。
