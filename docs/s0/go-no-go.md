# S0 Go/No-Go 评审记录

## 决策

- 评审状态：已完成当前架构的主设备技术门
- 结论：**NO-GO（普通消费者 App + 公开 API + MIUI 14 可靠撤销跳转）**
- 评审日期：2026-08-02
- 后续状态：S1 暂停；只有架构或产品承诺调整后，才能建立新的 S0 门
- 主测试设备：Redmi 23078RKD5C（corot），Android 13 / API 33，MIUI 14 V14.0，安全补丁 2023-10-01
- 诊断版本：v0.0.12-s0；Kotlin，minSdk 28、targetSdk 36

这不是对所有 Android 实现路径的否定。No-Go 的对象是计划 v1.1 当前要求的“大众版、无 Root、依赖公开 API、在首要 MIUI 平台可靠撤销跨应用跳转”架构。

## 判定依据

### 正式武装自动 100 次

测试配置为电池无限制、允许自启动、device-idle 白名单，以及用户明确启动并显示持续通知的前台服务。Home 回退关闭。测试目标退出后才由来源回传原始进入时间，避免目标侧真值广播在待测窗口内唤醒观察进程。

| 指标 | 成功/总数 | 点估计 | Wilson 95% | 门槛 | 结论 |
| --- | ---: | ---: | ---: | ---: | --- |
| 目标事件实时获取率 | 92/100 | 92% | 85.00%-95.89% | ≥95% | **失败** |
| 应阻止候选实时识别率 | 92/100 | 92% | 85.00%-95.89% | ≥93% | **失败** |
| 目标事件最终获取率 | 100/100 | 100% | 96.30%-100% | 仅诊断 | 8 次为解冻后迟到 |
| 允许流程误阻止率 | 0/15 | 0% | 0%-20.39% | ≤2% | 点估计干净，样本不足 |
| 已启动动作链的最终离开率 | 92/92 | 100% | 95.99%-100% | ≥90% | 通过 |

| 延迟 | P50 | P95 |
| --- | ---: | ---: |
| 候选生成 | 103 ms | 118 ms |
| 首次 Back | 227 ms | 243 ms |
| 最终离开目标 | 284 ms | 307 ms |

正式报告：[v0.0.12 武装自动 100 次](results/miui14-23078rkd5c-v012-armed-deferred-truth-stable100-greeze-gap8-20260802.report.json)。

及时识别的 92 次均只执行一次 Back 并成功离开，没有 Home、重复全局动作或其他安全违规。问题发生在动作链之前：观察进程被冻结时无法实时接收目标事件，因而 8 次没有候选和动作。最终到达不等价于实时阻断能力。

### 武装安全预检

- 手动单次：目标、候选、Back、离开各 `1/1`，候选/动作/离开为 101/225/285 ms；[报告](results/miui14-23078rkd5c-v012-armed-manual-single-inline-20260802.report.json)。
- 设置 5、Chrome 5、桌面 5：动作 `0/15`、候选 0、安全违规 0；[报告](results/miui14-23078rkd5c-v012-testsource006-armed-negative15-20260802.report.json)。
- 以上证明受控动作硬边界在本轮没有误触发，但 15 个允许样本不足以单独证明 `≤2%`。

### 根因与缓解复测

设备日志在漏处理窗口中同时显示：

1. MIUI Greeze 将主 App UID 10415 列入 `LM FZ` 冻结集合；
2. `com.jumpterminator.app.action.S0_TRUTH` 广播等待约 60 秒后超时；
3. Greeze 因该广播解冻 UID 10415；
4. 系统记录主线程约 60 秒停顿并完成 `com.jumpterminator.app` ANR。

该链路与时间线中的“实时缺失、最终补到”一致。完整摘录和边界说明见 [MIUI Greeze 调查记录](miui14-greeze-investigation.md)。

| 缓解方案 | 实时目标/候选 | 最终目标 | 结果 |
| --- | ---: | ---: | --- |
| 基线后台配置 + 前台服务 | 92/100 | 100/100 | 失败 |
| 实验性 Partial WakeLock，停止于 33 次 | 25/33 | 33/33 | 失败，代码已回退 |
| MIUI 最近任务锁，停止于 42 次 | 26/42 | 42/42 | 失败，锁已解除 |

复测报告：[Partial WakeLock](results/miui14-23078rkd5c-v013-armed-partial-wakelock-stable100-stopped33-gap8-20260802.report.json)、[最近任务锁](results/miui14-23078rkd5c-v012-armed-recents-locked-stable100-stopped42-greeze-failures-20260802.report.json)。两种复测都在再次出现同类冻结后提前停止，避免继续产生无价值的设备动作。

## 安全检查

- [x] 无无限 Back/Home 循环
- [x] 无关键系统界面动作
- [x] 身份未知时无动作（代码与单元测试闸门）
- [x] 主动回桌面后旧来源上下文不沿用
- [x] 每个及时识别的样本最多一次 Back；本轮 Home 为 0
- [x] 试验后恢复 `RECORD_ONLY`、关闭 Home 回退、停止前台服务并解除最近任务锁
- [ ] 允许流程 `≤2%` 的 200 次统计门；因主硬门槛已失败而未继续扩样
- [ ] 对照设备与 Android 9 实体机矩阵；架构调整前不再扩样

## 最终选择

- [ ] Go：进入 S1/S2
- [ ] Conditional Go
- [x] **No-Go：当前架构不得进入 S1**

理由：首要适配平台在正式 100 次中同时失败目标事件获取和候选识别硬门槛，且前台服务、系统后台放行、Partial WakeLock、最近任务锁均未消除 OEM 进程冻结。继续完成手动 100、允许 200 或跨设备矩阵不能挽救当前 MIUI 架构的既有硬失败。

报告 JSON 的 `provisionalDecision` 仍为 `NOT_READY`，因为统计工具只在完整矩阵齐备后输出 `GO`，且没有自动 `NO_GO` 状态。该机器字段不覆盖本评审依据计划硬门槛作出的人工 No-Go。

## 重新开门条件

满足以下任一方向后，创建新的 S0 方案和报告，不沿用本轮 Go 状态：

1. 改用能明确避免 OEM 冻结的 OEM/系统签名、Device Owner、专用设备或可验证特权伴侣架构；
2. 把产品承诺调整为“尽力而为的记录与提醒”，删除可靠阻止承诺并重设成功指标；
3. 获得可重复、可发布且不依赖隐蔽保活技巧的新方案，并在同一主设备上重新通过正式 100 次门槛。
